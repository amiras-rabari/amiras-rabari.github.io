Relational algebra query engine

An interpreter that reads relation definitions and one query, checks that the query is valid, and evaluates it in memory. It can also print the parse tree without running anything.

View code on GitHub

A multi-pass pipeline

  1. Input textRelation definitions, then exactly one query.
  2. TokenizerA modal lexer with maximal munch, escape decoding and line and column tracking.
  3. ParserRecursive descent. The grammar's shape encodes operator precedence and left associativity. LL(2) lookahead separates relation data from the query without backtracking.
  4. Semantic analyzerA schema catalog, column type inference, name resolution with ambiguity detection, and union-compatibility checks. Invalid queries are rejected before anything runs.
  5. ExecutorWalks the AST and evaluates 8 operators: select, project, rename, union, minus, intersect, times and theta join.

Design decisions

  • Memory safety. The AST is polymorphic with std::unique_ptr ownership and RAII, so a thrown error unwinds without leaking memory.
  • Cheaper joins. Join conditions are evaluated before building the combined tuple, so non-matching pairs are never allocated. Cartesian products are guarded by an overflow-safe size check.
  • Set semantics. Relational algebra works on sets, so duplicates are removed at load, projection and union.
  • One class per pass. Each stage has typed boundaries, and an AST-printing mode makes tree shapes easy to verify.

Measuring the join

A seeded data generator and machine-independent work counters benchmarked the nested-loop join up to 64,000 × 64,000 tuples. The counters matched n × m exactly, and the log-log slope of 2.05 confirmed quadratic growth.

A bug worth remembering

In a join, S.b was resolving to R.b. The fix was to carry fully qualified Relation.attr names all the way through execution instead of dropping the qualifier after parsing.
